# Roadmap

This is a proposal, not a release commitment. Contributions and issue reports
can influence priorities.

## Next (`0.2.x`)

- [ ] Expand fixture-based tests across real DOCX variations and Markdown extensions.
- [ ] Add golden-file round-trip regression tests and coverage reporting.
- [ ] Test macOS/Windows converter backends with opt-in integration tests.
- [ ] Improve CLI validation, diagnostics and image output safety.
- [ ] Validate release wheels and sdists on fresh virtual environments.

## Later (`0.3.x` and beyond)

- [ ] Better merged/nested tables, complex numbering and section handling.
- [ ] Improved mathematical expression coverage and graceful fallbacks.
- [ ] Explicit conversion profiles (GitHub Markdown, CommonMark, etc.).
- [ ] Structured warning/error codes and machine-readable conversion summaries.
- [ ] Optional trusted PyPI publishing once project naming and ownership are confirmed.

## Long-term ideas

- [ ] Embedded chart representations or downloadable assets.
- [ ] Resource ceilings and a dedicated security review for untrusted documents.
- [ ] API stability policy after a period of community feedback.

Use [GitHub issues](https://github.com/IsmailAzzouz/Doc2Md/issues) to suggest
features and discuss scope before submitting large changes.
